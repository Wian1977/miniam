# miniam — 用终端遥控 Apple Music

一个 Rust 写的全屏 TUI 遥控器：隐藏浏览器在 `music.apple.com` 上调用 `window.MusicKit`，
终端里显示频谱、封面与走马灯标题。声音由浏览器解码后送进系统混音器。

```
miniam (Rust + ratatui，全屏 TUI，16MB 单文件)
   └─ WebDriver BiDi（Firefox）或 CDP（Chrome）──> 隐藏浏览器（music.apple.com，已登录）
                           └─ 音频 → PipeWire/PulseAudio → 系统输出
```

## 范围

提供频谱、封面、标题显示，以及播放/暂停、切歌、频谱样式、页面诊断等按键控制。

音频由浏览器解码后送进系统混音器；浏览器进程树是架构刚需，已通过氛围视频抑制与 user.js 尽量压低（见「硬下限」）。

## 快速开始

```bash
cargo build --release

# 首次：会弹出可见浏览器窗口让你登录 Apple Music，登完按回车继续
miniam

# 之后：直接进界面（登录态存在 ~/.config/miniam/<browser>/ 里）
miniam
```

登录一次即可长期使用；Apple Music 的登录态由浏览器 profile 持久化。

**进界面后会自动起播**（不用再按任何键）：页面就绪（MusicKit 出队列）后自动回主页起播个人电台；
若 45 秒内页面仍未就绪（多半是没登录），也会尝试一次并给出提示。

## 乐段感知（启发式）

频谱会随音乐的能量起伏自动调整粒子密度、波环亮度和整体明暗：能量持续偏高且密集时略密略亮，能量塌落时收敛、整片压暗。默认与高能段维持改造前的亮度，只有弱段才向下收敛。按 c 键切换的四种呈现都生效——绿(经典)保持终端默认色、弱段变暗，霓虹线调火花密度，放射调拖尾与整片亮度，流体调波纹幅度与亮度。判定只用能量、低频、高频和谱通量的长时窗口（约 6 秒）与滞回，**不识别真实曲式**，对古典、爵士、环境音乐可能判错。纯本地算术，不新增依赖；音频仍只用于可视化，不落盘、不上传。

## 频谱插件架构

四种频谱样式各是一个独立插件，放在 `src/spectrum/`：

- `classic.rs` —— 经典绿（mode 0）。实际由 `draw_ui` 用 ratatui 原生 `Sparkline` 渲染，刻意保留与重构前一致的外观；`ClassicPlugin` 仍注册在 `make_plugin` 中，但输出不用于显示。
- `neon.rs` —— 霓虹粒子（mode 1）。
- `radial.rs` —— 放射（mode 2）。
- `fluid.rs` —— 流体（mode 3）。它有**自己的栅格化**（`raster_fluid`，按像素内容逐点打 braille 点），
  与其余模式共用的 `raster_braille`（按位置选固定点阵）分开 —— 后者会铺一张机械重复的背景点阵，
  盖住水波形状。

`mod.rs` 定义插件接口 `SpectrumPlugin` 与每帧传给插件的派生量 `SpectrumCtx`（相位 `phase`、节拍波前 `beat_wave`、起拍喷发 `do_burst`、淡入淡出 `fade`、霓虹色 `neon`）；`make_plugin(mode)` 按 `spec_mode` 静态创建对应插件。

主循环持有一个 `Box<dyn SpectrumPlugin>`，每帧调用 `renderer.render(spectrum, cols, rows, dyn_state, ctx)` 取回 braille 栅格行；按 `c` 切模式时重建 renderer（`spec_mode = (spec_mode + 1) % 4`）。每个插件自管跨帧状态（粒子池、流体水位等）。

后续规划（尚未实现）：约定运行时目录（如 `./spectrum_plugins/`），miniam 启动或运行中监控该目录、用 libloading 动态 dlopen 后填充注册表，做到放入文件无需重启即载入；届时 `make_plugin` 改为从注册表按索引取。

## 流体频谱（算法）

按 c 切到流体模式时，是一条**铺满整条频谱带**的水体：整条带都是深蓝的水，水面上浮着一条条**横向的浪脊**，浪脊随全局滚动量沿 y 上下流动 = 纵向流动感；带底还有一层守恒构造的「溅起水花」（撞底溅高、随后落回）。没有杯体、没有横向漂移。全部是纯算术、无外部依赖。

- **横向浪脊、纵向流动**：浪脊是横向的（铺满宽度的高光带），但运动方向是纵向的——几条浪头各是一个**高斯柔和亮核 + 外层辐射光晕**，配单向指数拖尾（头亮、向外柔和渐暗、方向可读），整体随 scroll 沿 y 滚动，像水底下泛起的辐射光。
- **跟节奏**：直接复用粒子 / 波前模式同一套节奏信号——流速 = 整体水位(avg) 基线 + busyness(谱通量+高频活跃度) + pulse(节拍脉冲，快起慢落)；踩点瞬间 pulse 把流速顶高、水花整体提亮、撞底溅起的水滴也窜得更高。安静慢、激烈快、每拍涌动，自然跟着音乐节奏走。
- **浪形跟随频率**：每个横向位置对应一个频段，浪脊的高度按该频段的能量起伏 —— 低频强的段落浪更高，高频强的段落浪更细碎。整条水带因此就是一条活的频谱波形。
- **点阵即水波**：水波用 braille 子像素逐点画出，**只有亮的地方才有点**（深水底是平滑底色，没有背景点阵），所以浪脊的形状是真的被点出来的，不是靠颜色蒙出来的。
- **配色**：电光蓝系（青蓝 → 深蓝，浪脊高光偏电光青），整体保持高饱和，不发灰、不发白。
- **底部溅起**：静态横向泡沫带被「抽」成上飞的水滴再回落，且亮度严格守恒（Σ 恒定），所以水滴怎么上飞、每列均亮都不变 —— 无横向漂移是数学保证而非调参。
- **频谱**：每列水位 = 该频段能量（带一阶惯性），低频/高频段拖尾长度与亮度不同，可读性更强。
- **不漂移**：浪脊与溅起都只沿 y 平移、亮度守恒，不沿 x 平移，画面不会横向漂移造成眩晕。

底晕铺满整条带，两端不会出现纯黑格子。

## 界面布局

纵向自上而下：

1. **最上面一行** —— 居中的状态行（`queue=3   backend=firefox(BiDi)`），一眼看到队列长度与后端。
2. 封面（专辑图 + 点阵标题带）
3. 歌曲信息跑马灯 · 播放态图标 · 时间行 · 进度条 · 帮助行
4. **最底边** —— 频谱带（4 行），紧贴窗口底边。

未播放音乐时频谱带整块留黑：没有声音时一条静止的假波形只会让人以为程序在「假装播放」。

## 命令行

```
miniam [ui|up|reset|cover]
```

- 无参数 / `ui` —— 一键：自动拉起浏览器、进入界面（未登录时引导登录）。
- `up` —— 只把浏览器拉起来常驻（之后另开终端跑 `miniam ui` 接管）。
- `reset` —— 清理残留的 miniam / 浏览器进程与虚拟音频设备。

## 音频链路

频谱只取被控的那一路音频。所以：

```
浏览器播放流 --move-sink-input(按 pid 精确匹配)--> miniam_capture   ← 频谱源
                                                                    │
                                       parec 抓 monitor → FFT      │ module-loopback
                                       （只含被控那一路）           │  → 真实输出 sink
```

两条设计要点：

1. **绝不改系统默认 sink。** 默认 sink 上挂着系统里其它声音（视频、系统音），
   一旦把默认 sink 改成频谱用的虚拟 sink，那些声音就会涌进频谱源 —— 表现为「放视频时频谱跟着跳」。
2. **按 pid 识别自己的浏览器**，不按二进制名 —— 你自己的 firefox 也叫 firefox。

因此：声音设置里会多一个 `miniam-频谱采集-勿选为输出` 的虚拟输出设备，**它是内部用的，
别选它**（null sink 不出声）。退出 miniam 时它会被自动卸载。

## 氛围视频抑制（省 CPU）

Apple Music 网页版会在背景里循环播放**氛围视频**（ambient video，14 个左右，单个最大
2048×2732，源在 `mvod.itunes.apple.com`）。这些视频与音乐无关（muted、`aria-hidden`），
但 Linux 上 Firefox **只能软解 HEVC**，实测会把整个浏览器抬到约 **217% 单核** —— 在 4 核机器上
就是整机一半的 CPU，而且解码供不上会让音频断流、曲目提前结束。

所以 miniam 会在页面里装一个抑制器（定时器 + MutationObserver，持续压住新出现的氛围视频），
靶子是页面自带的 `data-testid="ambient-video-player"` 官方标记，不会碰到承载音乐的媒体元素。
实测效果（4 核机器）：

| | 抑制前 | 抑制后 |
|---|---|---|
| HEVC 解码线程 | 4~12 | **0** |
| Firefox 整棵树 | 217% 单核（整机 54%） | **8% 单核（整机 2%）** |
| 整机 CPU busy | 99% | **14%** |

关掉它：`MINIAM_AMBIENT_VIDEO=0`。

## 封面渲染（象限块真彩）

封面用「象限块」渲染：每个字符格拆成 2×2 四个子块，整格只用两种 24-bit 真彩色
（前景 fg / 背景 bg），用 Unicode 象限字符表示哪几个子块取前景色。

**采样（物理正确）**：先把图缩放到 (列数·2, 行数·4)，**用面积平均**（BOX 滤波）；
再把每格切 2×2 子块，子块内取所有像素的均值 → 每格 4 个采样点。
不能用 LANCZOS/双线性把整图降采样后直接取点 —— 插值滤波会在色块边界产生假的中间色，
这就是边缘锯齿/发虚的来源。（`image` crate 只有插值滤波，BOX 面积平均是自己用积分图实现的。）

**两色指派（精确最优）**：穷举 14 种非平凡 fg/bg 指派（掩码 1..14，排除全 0 / 全 15），
fg = 被覆盖子块均值、bg = 其余均值，SSE = 各采样点到所属色的平方误差和，取 SSE 最小者。
不用 k-means / 亮度排序 / 硬阈值二值化 / 抖动。

实测（真实专辑封面，与「理想物理图」的偏差，越小越还原）：

| | 偏差 |
|---|---|
| 旧实现（插值降采样 + 逐点取样） | 280.1 |
| 现在（面积平均 + 子块平均） | **221.5（-21%）** |

字符表按 Unicode 真实语义索引（bit0 左上 / bit1 右上 / bit2 左下 / bit3 右下）：
`[空格,▘,▝,▀,▖,▌,▞,▛,▗,▚,▐,▜,▄,▙,▟,█]`。

离线比对用 `miniam cover`（输出纯 ANSI 文本，可直接在终端 cat）：

```bash
miniam cover ~/封面.jpg out.ans 90 36
```

## 浏览器省内存（站点隔离 / HEVC 解码器）

miniam 只用 music.apple.com 一个站，Firefox 的**站点隔离**（fission）没有安全收益，
却要多开 2~3 个内容进程。所以 miniam 拉起浏览器时会写两条 pref：

- 关掉站点隔离 + 内容进程数=1 → 内容进程从 3~4 个降到 1 个
- 关掉 HEVC 解码器 → 氛围视频被抑制器压住后，解码器留着只是占着内存
  （音乐本身是 AAC/ALAC，不受影响）

实测（4 核 / 8G）：

| | 全默认 | 加上这两条 |
|---|---|---|
| Firefox 进程数 | 12 | **9** |
| Firefox RSS | ~2890M | **1800M** |
| 其中 RDD 媒体进程 | ~600M | **219M** |

恢复默认行为：`MINIAM_FISSION=1`（站点隔离）、`MINIAM_HEVC=1`（HEVC 解码器）。

## 常见故障速查

| 现象 | 多半是 |
|---|---|
| 频谱没反应 | 浏览器没在播放；或浏览器流没被接进频谱源。查 `pactl list sink-inputs` 里有没有我们那个浏览器的流、`/tmp/miniam_audio.log` 是否有「未能识别浏览器进程」 |
| 放视频时频谱跟着动 | 有别的流（你自己的 firefox / 播放器）被留在频谱源里了。查 `pactl list sink-inputs` 对比 `application.process.id` 与 `/proc/<pid>/cmdline`（我们的浏览器带 `--profile ~/.config/miniam/`） |
| 完全没声音 | ① 默认 sink 被残留污染（跑 `miniam reset`）；② 无声卡服务器需修 `/dev/snd` 的 ACL 或加入 `audio` 组；③ 真实输出 sink 不存在 |
| 登录窗口不弹 | 浏览器没真起来（profile 被上次残留占用）；或会话没有图形显示（需要 DISPLAY/WAYLAND_DISPLAY，或 `ssh -X`） |

## 硬下限（再强调一次）

Apple Music 网页版的播放由浏览器内的 MusicKit 完成，所以必须使用真实的 Firefox 或 Chrome，并加载官方页面。
浏览器的内存占用是架构刚需，省不掉整个进程树；能省的是控制面那十几 MB，
以及浏览器本身的启动参数与内存占用 —— 氛围视频抑制器压住 CPU，
user.js 里的 `dom.ipc.processCount=1`、关站点隔离、关 HEVC 解码器把进程数
12→9、RSS ~2890M→1800M（见「浏览器省内存」）。

换轻量浏览器或自托管一个简化页面都无法加载官方播放器，
这条路上已经验证过走不通。
